# M2 crawler architecture and acceptance

## Implementation
NestJS queues a MongoDB crawl job in the same transaction as permission checking and audit creation; requests never run the crawl. An independent BullMQ worker polls queued MongoDB jobs every five seconds and enqueues an idempotent job ID. This serves as a durable dispatch outbox if Redis is temporarily down. Only active, ownership-verified websites are eligible. Writer roles: Owner, Admin, Marketing Manager, SEO Manager. All active workspace members may read their own website's evidence. API and worker recheck tenant/site scope; domain change/archive invalidates in-flight processing. Partial unique index allows one active job per workspace/site. Version checks guard cancel/retry requests. Cancellation leaves prior completed inventory unchanged.

MongoDB collections: crawl_jobs (configuration/counters/status), crawl_pages (immutable per-run page snapshots), website_urls (current inventory), crawl_errors, discovered_links, robots_records, sitemap_records and technical_issues. All carry orgId/websiteId, timestamps, source/status. No additional duplicate crawl_snapshots collection: crawl_pages provides the historical snapshot. Unique job/url and website/url hashes prevent duplicate processing/storage. Worker execution IDs fence writes after cancellation or restart. Technical issue records use severity/type/why/recommendation, reusable by M7.

Full, sitemap and single-URL modes; default 100 pages, maximum 500. URL normalization removes fragments, sorts query parameters and retains trailing-slash/path distinctions. Discovery follows nested sitemaps (20-file ceiling, 5,000 entries/file) and internal follow links. Scope is exact hostname, HTTP/HTTPS only, default ports only. Subdomains and external links are recorded but not followed; external HTTP statuses remain explicitly unchecked. Inventory is published only when a run completes; each URL identifies its source job/time and older URLs remain until a subsequent observation, not falsely marked deleted.

Robots: honors user-agent allow/disallow rules and crawl-delay up to 60 seconds; longer delays reject the job. Missing robots (404/410) permits fetching; other failed robots retrieval fails closed. Redirects check scope and robots again. XML rejects DOCTYPE/entity declarations. Non-HTML responses record fetch metadata but are not parsed as HTML. Orphan and duplicate-content findings are candidates bounded by crawl coverage. No fabricated health score is displayed.

## Network and worker controls
Global Redis host pacing defaults to one request/second, including redirects and JS subresources, and honors robots delay. Worker concurrency is two across websites. Fetches have 10-second deadlines, DNS five-second budget, 2-MB response cap, five-redirect cap and two transient network attempts. Public-IP checks cover IPv4, IPv6 and mapped IPv4; every DNS result must be public, then the connection is pinned to the vetted address to prevent rebinding. Credentials/non-default ports/alternate protocols are rejected. HTTPS certificate validation stays enabled.

JavaScript rendering is optional and disabled by default. When explicitly enabled, install Chromium with Playwright dependencies and verify sandbox support in an isolated worker. Browser requests are intercepted and fulfilled through the same safe fetcher, with a dead outbound proxy, loopback bypass disabled, service workers blocked, websockets closed, GET-only requests and bounded resource/body/time budgets. Enable CRAWLER_RENDER_JS on both API and worker only after live browser security/load acceptance. Do not disable the Chromium sandbox to make deployment pass.

## UI contract
Settings → Websites → Crawls opens the selected website without changing the ten-module sidebar. Crawls shows actual status, counters, progress, timestamps, elapsed duration, errors and last URL. Polling every five seconds stops outside the active view or while forms are open. Start uses the existing modal, validates mode/page limits/URL/JS setting; robots is always enforced. Cancel requires confirmation. Retry/re-run creates a new historical run. URL Inventory supports status/indexability/sitemap/issues/content type/redirect/error/search/sort and pagination. Detail modal displays fetch information, metadata, headers, headings, schema, links, images, issues and recent history. Crawl report shows issue severity/recommendations, robots source, sitemap entries and paginated errors. Empty/error/loading states reuse foundation patterns. Unauthorized write actions are hidden; backend remains authoritative.

## Environment and deployment
Existing deployment remains disabled for crawl submission until CRAWLER_ENABLED=true and REDIS_URL are configured. Start worker: npm run worker --prefix backend. Run migrations before traffic. Redis uses noeviction and durable storage; MongoDB queued jobs survive dispatch failure. render.crawler.yaml describes a separately deployable paid worker and durable Key Value instance; it is not automatically applied. Configure the same private REDIS_URL on API and worker, then RATE_LIMIT_STORE=redis on API. Review pricing and resources before provisioning. Monitoring must alert on queued-job age, failed jobs, worker disconnects and Redis memory pressure. SIGTERM drains worker work; BullMQ recovers interrupted jobs. Running jobs with no heartbeat for ten minutes are atomically failed with WORKER_HEARTBEAT_EXPIRED, releasing the active-job slot for explicit retry. A resumed old worker cannot publish after this transition. Fresh and queued jobs are not expired. Pausing is not offered.

## Acceptance evidence / gates
Local pure/unit/DOM tests cover normalization, unsafe addresses, robots, sitemap parsing, extraction, canonical logic, issue detection, crawler states and permission hiding. CI integration uses real MongoDB and Redis/BullMQ with deterministic test page responses (no production network bypass): queue → crawl → nested sitemap → snapshots/inventory/issues → filtered details → retry/cancel → tenant denial. Test fixtures deliberately pre-verify isolated website records; this does not prove real DNS ownership.
